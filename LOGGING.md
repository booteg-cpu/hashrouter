# Диагностика Hash Router 82.0.19

INFO: запуск/остановка, конфигурации, каталог алгоритмов, подключение/авторизация входов и выходов, первые задания, отключения, ошибки, повторные подключения, истечение источника и сводки выходов каждые 30 секунд.

DEBUG дополнительно записывает задания, сложность, переключения выходов и результат каждой шары со временем ответа. Включайте для замеров: он увеличивает объём журнала. Сырые Stratum-сообщения, заголовки HTTP, ключи, пароли и текст исключений не записываются. Известные реквизиты дополнительно исключаются из текстовых полей.

В SBP 82.0.19: **Hash Router → Логи роутера → VPS**. Фильтры алгоритма/уровня, автообновление 3 секунды, переключение DEBUG на сервере, сохранение полученных строк JSONL. Переключение уровня временное: после рестарта действует `log_level` из `/etc/hash-router/config.json` (по умолчанию INFO). Маршрутизация не меняется.

`router-events.jsonl` хранится рядом с файлом состояния (обычно `/var/lib/hash-router`). Ротация: текущий файл до 5 MiB и три предыдущих. API отдаёт последние 2000 событий, по 1–500 за запрос. Окно SBP хранит до 5000 полученных строк; сохранение экспортирует их, а не полный архив VPS. Пропуски отмечаются явно.

Служба пишет на диск в отдельном потоке с очередью 4096 событий. Заполненная очередь пропускает запись на диск, не задерживая Stratum; счётчик виден в API/SBP. При ошибке диска доступен буфер памяти. Авария процесса может потерять ещё не записанный хвост. Сохранённый хвост восстанавливается после рестарта; обновление не удаляет архивы.

API использует прежние HTTPS, токен и проверку сертификата:

- `GET /v2/logs?after=0&limit=300&level=DEBUG&algorithm=scrypt&stream=...` — записи, курсор `next`, идентификатор `stream`, флаги `gap`/`reset`, состояние записи на диск. Пустой algorithm выбирает все алгоритмы. Следующий запрос передаёт возвращённые next и stream; курсор учитывает строки, исключённые фильтром.
- `PUT /v2/logging` с JSON `{"level":"DEBUG"}` или `{"level":"INFO"}` — временный уровень.

Оба endpoint требуют авторизации. MRR не используется. Успешные GET журналов/статуса не создают собственных событий.

Если служба не запустилась или HTTPS недоступен, журнал через SBP недоступен. Для диагностики запуска по SSH: `sudo journalctl -u hash-router -n 100 --no-pager`.

Проверки выпуска: 67 серверных тестов и 124 теста SBP прошли офлайн; живые MRR/VPS/ASIC не использовались.
