# Hash Router 82.0.13

Экспериментальный сервер Stratum для Debian 12/13, Python 3.11+.
Принимает мощность одного алгоритма и распределяет её между заданными
выходами и пулом остатка. Разные алгоритмы обслуживаются отдельно.

Этот репозиторий содержит только сервер, установщик и серверные тесты.
Приложение SBP хранится отдельно и управляет заданиями через HTTPS API;
роутер самостоятельно не арендует риги, не создаёт объявления и не меняет цены.
Ключи API MRR серверу не нужны.

## Установка

Клонируйте публичный репозиторий на VPS и выполните:

```bash
git clone https://github.com/booteg-cpu/hashrouter.git
cd hashrouter
sudo bash install-router.sh
```

Установщик спросит публичный IP/домен и порт HTTPS API (обычно 8443),
создаст токен и TLS-сертификат, установит и включит службу hash-router.
В панели провайдера разрешите показанные установщиком TCP-порты
(обычно API 8443 и Stratum 3333–3433).

Для подключения без переноса файлов сохраните показанные в SSH-терминале:
IP/домен VPS, порт API, ключ доступа и SHA-256 отпечаток TLS-сертификата.
В клиенте с поддержкой закрепления сертификата введите IP, порт и ключ,
сверьте отпечаток через доверенное SSH-соединение и подтвердите его один раз.
Ключ отправляется только после проверки сертификата. При смене сертификата
потребуется повторная сверка; отключать проверку HTTPS не нужно.
SBP передаёт каталог алгоритмов и задания маршрутизации через существующий API v2;
Stratum-порты назначает роутер. Настройте и включите алгоритмы в SBP.

**Совместимость:** текущая SBP 82.0.11 ещё требует импорт CA для сертификата
установщика. Подключение по отпечатку требует обновления клиента; этот выпуск
содержит только роутер. Для прежнего клиента файл можно создать отдельно:

```bash
sudo python3 deploy/hash_router/setup_connection.py --host YOUR_VPS_IP --export-connection
```

Затем скопируйте `/etc/hash-router/sbp-connection.json` через SSH/SFTP и импортируйте
в SBP. По умолчанию установщик этот файл не создаёт. Ранее созданный файл сохраняется.
Файл и показанный ключ дают доступ к управлению: не публикуйте их.

## Проверки и обновление

```bash
sh install-router.sh --check
sudo systemctl status hash-router
sudo journalctl -u hash-router -n 50
```

`--check` проверяет комплект без установки. Повторная установка сохраняет
`/etc/hash-router/config.json`, токен и `/var/lib/hash-router/state.json`,
но останавливает службу на время обновления: подача хэша прервётся.
Подробности TLS и обновления: [инструкция](deploy/hash_router/README.md).

Тесты с локальными имитаторами:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r deploy/hash_router/requirements.txt
.venv/bin/python -m unittest discover -s tests_hash_router -t . -v
```

Версия 82.0.13 добавляет вывод отпечатка и необязательный экспорт подключения. Движок и API
совместимы с предыдущей сборкой; живое оборудование этими тестами не проверяется.
